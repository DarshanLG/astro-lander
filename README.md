# Astro Lander

Teaching a rocket to land itself with reinforcement learning:

- **PPO written from scratch** in PyTorch (GAE, clipped objective, vectorized rollouts, truncation bootstrapping, observation and reward normalization), validated against Stable-Baselines3 under identical hyperparameters.
- **A reward-shaping study.** The same agent is trained on four reward functions: Gymnasium's default, **potential-based shaping** (Ng et al., 1999), a naive "be near the pad" bonus, and a sparse terminal-only reward. All are measured on the true task.
- **Robustness via domain randomization.** Gravity, wind and turbulence are re-sampled every episode, then the agent is stress-tested on a grid of conditions it never trained on.
- **A live browser demo.** Gymnasium's Lunar Lander is ported line-for-line to JavaScript (planck.js), and the trained network runs in the page. You can turn up the storm and watch it cope. Because the policy was trained in Python Box2D, this also measures **sim-to-sim transfer**.

> Results tables, figures and GIFs are generated by `scripts/analyze.py` into `results/` and added here after the experiments run.

## Project layout

```
astro_lander/
  envs.py        env factory + wrappers: LandingMetrics, RewardShaping, DomainRandomization
  ppo.py         PPO from scratch (config, networks, normalizers, training loop, Policy save/load)
  evaluate.py    held-out evaluation, stress-test grid, GIF rendering
scripts/
  train.py             train one agent
  run_experiments.py   full experiment matrix (parallel, resumable)
  sb3_baseline.py      Stable-Baselines3 reference run, same hyperparameters
  analyze.py           evaluate all runs, make figures + tables
  export_policy.py     export a trained policy to JSON for the web demo
web/
  index.html     interactive demo
  lander.js      Lunar Lander physics ported to planck.js + MLP policy runner
  parity_test.js runs a policy in the JS engine and reports outcome stats (Node)
tests/           pytest suite (wrappers, PBRS math, normalizers, training smoke test)
configs/         optional JSON overrides for train.py
```

## Setup

Needs Python 3.10–3.13 (Box2D has prebuilt wheels for these on Windows, macOS and Linux).

```bash
python -m venv .venv
source .venv/Scripts/activate      # Git Bash on Windows; macOS/Linux: source .venv/bin/activate
pip install -r requirements.txt
pytest -q
```

## Reproduce

```bash
# one agent (~10-15 min on CPU)
python scripts/train.py --seed 1

# everything: implementation check, shaping ablation, robustness, continuous control (3 seeds each)
python scripts/run_experiments.py

# evaluate on 100 held-out episodes per run, stress tests, figures, GIFs -> results/
python scripts/analyze.py

# web demo: export the two showcase agents, then serve the folder
python scripts/export_policy.py runs/disc_default_rand_s1/final.pt web/policies/robust.json --label "Robust"
python scripts/export_policy.py runs/disc_default_s1/final.pt web/policies/nominal.json --label "Calm-trained"
python -m http.server 8000 --directory web      # open http://localhost:8000
```

## How it works

**Observation (8):** x, y, vx, vy, tilt, angular velocity, left/right leg contact.
**Actions (4):** coast, left jet, main engine, right jet. A continuous variant controls throttle.

**Reward shaping.** The default reward adds a dense shaping term to the sparse ±100 landing/crash signal. Shaping speeds up learning, but it can also change *what* is learned. Potential-based shaping, `F = γΦ(s') − Φ(s)`, is the one form proven to leave the optimal policy unchanged. The naive variant pays the agent every step it is near the pad, and it is included to show reward hacking (hovering forever instead of landing). Every scheme is scored on the same true task return, recorded by a wrapper that sits underneath the shaping.

**Evaluation is separate from training.** Training logs use the shaped reward and a stochastic policy. Reported numbers use the deterministic policy on 100 held-out seeds that training never uses.
